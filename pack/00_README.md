# حزمة بناء نظام HRMS

هذه الحزمة مكمّلة للوثيقة الرئيسية «مواصفات بناء نظام شؤون الموظفين والحضور والانصراف (HRMS)». الوثيقة تشرح **ماذا** و**لماذا**، والحزمة تعطي المنفذ **العقود الدقيقة**.

| الملف | المحتوى | يقابل قسم الوثيقة |
|---|---|---|
| 01_schema.sql | سكربت SQL Server كامل: 81 جدولاً، مفاتيح أجنبية، قيود CHECK، فهارس فريدة (تتجاهل المحذوف منطقياً)، 3 عروض | 8 |
| 02_seed.sql | 248 صلاحية، وإجراء `hr.usp_SeedCompanyDefaults` الذي يزرع لكل شركة: الأدوار السبعة وربطها بالصلاحيات، القوائم الثابتة، أنواع الإجازات، بنود الرواتب، أنواع الوثائق والاستئذان | 3.5، 6 |
| 03_openapi.yaml | عقد OpenAPI 3.0.3 صالح: 173 مساراً و319 عملية، ومخططات مولّدة من الجداول نفسها، وصلاحية كل عملية في `x-permission` | 9 |
| 04_permissions_matrix.md | مصفوفة الأدوار × الموارد × الإجراءات | 3.5 |
| 05_phase_prompts.md | Prompt جاهز لكل مرحلة تلصقه في أداة الذكاء الاصطناعي | 13 |

## ترتيب الاستخدام
1. أنشئ قاعدة بيانات فارغة ونفّذ 01 ثم 02.
2. أدخل صفاً في `hr.Companies` ثم نفّذ `EXEC hr.usp_SeedCompanyDefaults @CompanyId = <id>`.
3. أعطِ أداة الذكاء الاصطناعي: الوثيقة الرئيسية + 01 + 03 + 04، ثم Prompt المرحلة 1 من الملف 05. لا تعطها كل المراحل دفعة واحدة.
4. بعد كل مرحلة، اختبر معايير القبول في القسم 13 قبل الانتقال للتالية.

## ما يجب أن تعرفه
- القيم الافتراضية للإجازات والبنود في 02 أمثلة فقط؛ عدّلها حسب قانون العمل في بلدك.
- حقول `IdentityNo` و`PassportNo` و`BankAccount` بحجم 200 لأنها تُخزَّن مشفّرة من طبقة التطبيق.
- الجداول غير المولَّدة منطقاً (احتساب الحضور، الرواتب) لا تحتويها الحزمة؛ مرجعها القسمان 5 و6 من الوثيقة، وهما سبب وجود اختبارات الأمثلة العددية.
- سكربت SQL فُحص نحوياً بمحلل T-SQL ولم يُشغَّل على خادم فعلي. شغّله على قاعدة تجريبية أولاً وأبلغ المنفذ بأي خطأ.
